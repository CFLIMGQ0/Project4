# EUS-GIST-Leiomyoma 项目说明

## 1. 项目名称
**EUS-GIST-Leiomyoma：胃肠道间质瘤（GIST）与平滑肌瘤（Leiomyoma）影像分类研究项目**

---

## 2. 项目简介
本项目面向胃肠道黏膜下肿瘤相关的医学影像分类研究，聚焦于**胃肠道间质瘤（GIST）**与**平滑肌瘤（Leiomyoma）**两类病变的鉴别任务。当前以工程化研究仓库形式组织，强调：

- 数据说明先行
- 患者级样本管理
- 可复现的划分与训练流程
- 逐阶段迭代（先 SCI-4，再考虑后续扩展）

本仓库当前用于支持第一阶段任务（SCI-4），暂不展开更高阶段的具体实现细节。

---

## 3. 当前阶段目标（仅 SCI-4）
当前阶段仅聚焦于四区论文任务：**SCI-4**。

阶段目标包括：
1. 明确并固化数据组织说明（患者级结构、模态作用、使用边界）；
2. 建立两个单模态分类任务的基线开发框架；
3. 严格落实患者级数据划分，避免数据泄漏。

> 说明：当前阶段不扩展到 SCI-3、SCI-2 的具体技术方案，仅在“后续规划”中简要提及。

---

## 4. 当前研究任务
### 4.1 白光胃镜单模态分类任务
- 输入：患者目录中的白光胃镜图（WLE，常见命名为 `2.png`）。
- 目标：完成 GIST vs Leiomyoma 的二分类基线。
- 备注：仅使用图像模态，不引入文本模态。

### 4.2 EUS 单模态分类任务
- 输入：患者目录中的 EUS 静态图（常见命名为 `3.png` 至 `n.png`）。
- 目标：完成 EUS 单模态二分类基线。
- 备注：单患者可能对应多张 EUS 图，训练前需设计患者级样本聚合或图像级采样策略（待补充）。

---

## 5. 数据组织概览（详细见 DATASETS.md）
当前原始数据采用患者级目录组织：

- 数据集根目录下包含多个患者文件夹；
- 每个患者文件夹通常包含：
  - 1 张检查报告截图（常见 `1.png`）；
  - 1 张白光胃镜图（常见 `2.png`）；
  - 多张 EUS 图像（常见 `3~n.png`）。

实际数据中可能存在命名不完全统一、个别文件缺失等情况，**以原始数据实际内容为准**。

---

## 6. 当前项目原则
1. **患者级建模优先**：数据组织与分析以患者为基本单位。  
2. **患者级划分**：同一患者的所有图像必须进入同一数据子集（train/val/test）。  
3. **报告截图不作为当前模型输入**：SCI-4 阶段仅用于核对、元数据整理与标签辅助确认。  
4. **当前阶段不做文本模态**：不构建报告文本输入模型，不进行多模态融合训练。  
5. **不对原始目录做破坏性改造**：不要求重命名、移动或覆盖原始数据文件。

### 7.1 训练输出目录规范（新增）
为便于后续模型迭代与结果追踪，约定每次训练均在输出根目录下创建“**编号+训练目录名**”的独立子目录。

推荐命名格式：

```text
/home/Lim/outputs/eus-gist-leiomyoma/
└─ 1_eus_baseline_resnet18/
└─ 2_wle_baseline_efficientnet_b0/
└─ 3_eus_ablation_aug_v2/
```

说明：
1. `1/2/3...` 为递增阿拉伯数字编号（前面不补 0），用于保证实验顺序可追溯；
2. 下划线后的目录名用于描述本次训练主题（如模态、骨干网络、实验目的）；
3. 具体的 `xxx` 命名可按后续实验计划单独指定；
4. 单次训练的日志、权重、评估指标、配置快照等均放在对应子目录内；
5. 若需重跑同一实验，建议使用新编号并在目录名中补充 `rerun`/`seed` 等标记。

## 13. 预处理脚本产物说明（已实现）
当前 `scripts/preprocessing.py` 的输出调整为两类记录：

1. **患者级报告记录（每个患者目录内）**
   - 文件名：`report.csv`
   - 结构：纵向键值（两列：`字段`、`值`），会按参数选择是否覆盖旧文件。
   - 主要字段包括：姓名、性别、年龄、检查号、病区-床号、门诊号、病案号、检查日期、申请科室、机型、诊断描述、镜下诊断、检查图象；
   - 同时包含总结信息：
     - 类别（四分类）：间质瘤 / 可能间质瘤 / 可能平滑肌瘤 / 平滑肌瘤；
     - 是否有 WLS、WLS 图像数；
     - 是否有 EUS、EUS 图像数。

2. **全体患者汇总记录（全局输出目录）**
   - 文件名：`patient_summary.csv`
   - 结构：每个患者一行，便于后续统计、筛选与划分。

示例命令：

```bash
python scripts/preprocessing.py \
  --dataset-root /home/Lim/.cache/kagglehub/datasets/eus_dataset \
  --output-dir /home/Lim/projects/eus-gist-leiomyoma/data/manifests \
  --overwrite-report-csv
```

## 14. 患者姓名一致性核验脚本（已实现）

> 说明：当前项目中同时约定两个名称：
> - `all_patients_raw.xlsx`：历史上“原始台账”文件名（旧名，主要用于兼容旧脚本/旧说明）；
> - `all_patients.xlsx`：你当前正在维护和实际使用的主文件名（新名，`check_data.py` 默认优先读取该文件）。
>
> 建议后续统一以 `all_patients.xlsx` 作为主数据文件，并仅在需要兼容历史流程时提及 `all_patients_raw.xlsx`。
使用 `scripts/data_cleaning/check_data.py` 检查 Excel 患者姓名与数据集患者目录是否一致，结果直接打印到终端，不生成 `.md` 报告文件。

- 显式传参（推荐）：

```bash
python scripts/data_cleaning/check_data.py \
  --dataset-root /path/to/eus_dataset \
  --excel-path /path/to/all_patients.xlsx
```

- 不传 `--dataset-root` / `--excel-path` 时，脚本会按以下顺序自动尝试常见路径：
  - `data/raw/eus_dataset`
  - `data/eus_dataset`
  - `~/.cache/kagglehub/datasets/eus_dataset`
  - `data/raw/all_patients.xlsx`
  - `data/all_patients.xlsx`
  - `all_patients.xlsx`

若自动识别失败，脚本会提示你补充必填参数。
